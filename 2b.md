# FlashTerminal Phase 2B

## Real Agent Adapters + Provider + BYOK Foundation

FlashTerminal Phase 2A is complete.

Current validated architecture:

```text id="l2kfz7"
Workspace
  ↓
Pane
  ↓
ExecutionId
  ↓
ExecutionKind
  ├── TerminalSession
  └── AgentSession
        ↓
    AgentRuntime
        ↓
    AgentAdapter
```

Phase 2A established:

* generic execution abstraction
* AgentSession
* AgentRegistry
* AgentRuntime
* AgentAdapter
* AgentState
* AgentEvent
* deterministic fake-agent
* IPC agent commands
* application-level events
* persistence metadata
* fairness-aware agent output handling

The current GenericCliAdapter is only a foundation and does not yet provide the full production-grade bidirectional PTY behavior required by real interactive coding agents.

Phase 2B must now turn the Agent Runtime into a real execution environment.

---

# 1. Primary Objectives

Phase 2B has four objectives:

1. Implement real bidirectional agent execution.
2. Implement real adapters for major agents.
3. Introduce a clean Provider / Model abstraction.
4. Introduce secure BYOK credential storage.

The initial real agents are:

```text id="c4xka3"
Claude Code
OpenAI Codex
OpenCode
Pi
```

Do NOT implement multi-agent orchestration yet.

Do NOT implement task graphs yet.

Do NOT implement agent-to-agent communication yet.

---

# 2. Critical Architecture Rule

Keep these concepts strictly separate:

```text id="o22uuq"
Agent
Provider
Model
Credential
Execution
Workspace
```

Example:

```text id="9k5f9a"
Agent:
Claude Code

Provider:
Anthropic

Model:
Claude model

Credential:
Anthropic API key
```

Another:

```text id="vsyc22"
Agent:
OpenCode

Provider:
OpenRouter

Model:
arbitrary selected model

Credential:
OpenRouter API key
```

Do not collapse these into one object.

# 4. Agent Process Model

Agent processes should behave like real interactive execution sessions.

Example:

```text id="3g8q4l"
AgentSession
   ↓
AgentAdapter
   ↓
PTY/process
   ↓
terminal output
   ↓
AgentEvent / terminal rendering
```

The user must be able to interact with an agent running in a pane.

---

# 5. Raw Terminal Compatibility

Every supported CLI agent must work in a normal terminal.

Do not require structured APIs merely to display output.

The minimum fallback is:

```text id="nfs94q"
stdin/stdout/stderr
PTY
process lifecycle
```

Higher-level structured capabilities can be added on top.

# 7. Agent Adapter Contract

Strengthen `AgentAdapter`.

It should expose only capabilities that can actually be supported.

Conceptually:

```rust id="b3p5g9"
AgentAdapter {
    definition()
    spawn()
    send_input()
    stop()
    restart()
    inspect_capabilities()
}
```

Optional capability interfaces may include:

```text id="cf8gnt"
Resume
Pause
StructuredEvents
Usage
Approval
Hooks
```

Do not create fake implementations.

# 16. BYOK Credential Architecture

API keys must NOT be stored in:

```text id="nqoqaa"

agent JSON
SQLite plaintext
environment snapshots
logs
IPC messages
```

Use native OS credential storage.

macOS:

```text
Keychain
```

Design equivalent providers for:

```text id="pmlyc9"
Linux
Windows
```

later.

# 20. Agent / Provider Relationship

The architecture should allow:

```text id="y5azv8"
Claude Code
    ↓
Anthropic credential
```

and independently:

```text id="6ol4w0"
OpenCode
    ↓
OpenRouter credential
    ↓

```

The Agent Runtime must not care how the provider credential is stored.

---

# 21. Environment Injection

Where an external CLI agent expects credentials through environment variables:

```text id="zj6i6h"
Credential Store
      ↓
Agent Launch Context
      ↓
Environment
      ↓
Agent process
```

Do NOT persist the resolved secret.

Do NOT expose it through IPC events.

Do NOT include it in logging.

Clear or minimize exposure after process initialization where technically possible.

---

* task graphs
* agent teams
* automatic model routing
* agent-to-agent messaging

* autonomous task decomposition
