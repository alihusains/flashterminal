# FlashTerminal Phase 3E

## Adaptive Orchestration + Controlled Replanning

FlashTerminal Phase 3D is complete.

Current validated system:

```text id="x0eykp"
User Intent
   ↓
Planner
   ↓

   ↓

   ↓
ExecutionEnvironment
   ↓
WorktreeManager
   ↓
AgentRuntime
   ↓

   ↓
TaskResult
   ↓

   ↓
Review / Synthesis
```

Phase 3D established:

* ArtifactStore

* ArtifactLineage
* ArtifactAccessPolicy

* structured TaskResult
* ReviewFinding

The workspace is now capable of deterministic multi-agent collaboration.

Phase 3E introduces **adaptive orchestration**.

---

# 1. Primary Objective

Enable FlashTerminal to detect when an executing workflow is no longer aligned with the original plan and safely propose a revised plan.

The loop is:

```text
Plan
 ↓
Execute
 ↓
Observe
 ↓
Evaluate
 ↓
Replan Signal
 ↓
Planner
 ↓
Proposed New Plan
 ↓
Validator
 ↓
Human Approval
 ↓
Continue
```

The deterministic orchestration engine remains authoritative.

---

# 2. Critical Rule

The Planner may propose a new plan.

The Planner must NOT directly mutate or execute the workflow.

Never allow:

```text
Agent
 ↓
LLM
 ↓
spawn task
```

The only valid path is:

```text
Evidence
 ↓
Replan Signal
 ↓
Planner
 ↓
ProposedPlan
 ↓
PlanValidator
 ↓
Human Approval
 ↓
TaskGraph
 ↓
TaskScheduler
```

---

# 3. ReplanTrigger

Create a formal:

```text
ReplanTrigger
```

Possible triggers:

```text
TaskFailure
CriticalReviewFinding
RepeatedRetryFailure
ArtifactMissing
DependencyInvalidated
BudgetRisk
EnvironmentFailure
TestsFailed
MergeConflict
ManualUserRequest
```

Keep the initial taxonomy small.

---

# 4. ReplanSignal

Create:

```text
ReplanSignal
```

with:

```text
id
workflow_id
task_id
trigger
severity
reason
evidence_artifacts
created_at
```

The signal must be persisted.

---

# 5. Replan Severity

Use:

```text
Info
Warning
Critical
```

Example:

```text
Tests failed
→ Warning
```

versus:

```text
Security review found critical vulnerability
→ Critical
```

The severity does not automatically trigger execution.

It controls UI/approval behavior.

---

# 6. Workflow Evaluation

Create:

```text
WorkflowEvaluator
```

Responsibilities:

```text
observe task results
observe review results
observe artifacts
observe failures
detect invalid assumptions
produce replan signals
```

Keep it deterministic initially.

Do not ask an LLM to detect every failure.

---

# 7. Deterministic Evaluation Rules

Implement initial deterministic rules:

```text
test failure
→ Replan candidate

critical review finding
→ Replan candidate

required artifact missing
→ Replan

merge conflict
→ Replan candidate

budget exceeded
→ Replan / Stop

task repeatedly failed
→ Replan candidate
```

The evaluator must be predictable.

---

# 8. Replan Deduplication

Do not create:

```text
100 identical test failures
→ 100 replan signals
```

Coalesce equivalent signals.

A dedupe key could use:

```text
workflow_id
task_id
trigger
evidence fingerprint
```

---

# 9. Replan Cooldown

Create a configurable cooldown.

Example:

```yaml id="3t4tyg"
replan_cooldown_seconds: 30
```

This prevents an unstable workflow from generating rapid replanning requests.


# 17. Replan Execution

After approval:

```text id="m4w4r3"
Approved Replan
 ↓
TaskGraph migration
 ↓
Scheduler
```

Do not destroy completed historical work.

Completed tasks remain completed.

Only affected portions of the graph should change.

---

# 18. Task Preservation

When replanning:

```text id="wbq8l3"
Completed
```

tasks remain completed unless explicitly invalidated.

For example:

```text
Research ✅
Implementation ❌
Tests blocked
```

A new plan may retain:

```text
Research ✅
```

without rerunning it.

---

# 19. Task Invalidation

Allow explicit:

```text id="zjvkh7"
TaskInvalidated
```

when evidence proves a previously completed task is no longer valid.

This requires:

```text id="y9pq9s"
reason
evidence
```

and should normally require human approval.

Do not let the planner silently invalidate completed work.

---

# 20. Artifact Invalidation

Similarly:

```text id="5saqbb"
ArtifactInvalidated
```

may occur when:

```text
source changed
artifact superseded
review found invalid assumptions
```

Preserve the old artifact for lineage.

Do not delete it.

---

# 21. Replan Safety

A replanned workflow must not:

* exceed max agents
* exceed budget
* bypass permissions
* use unavailable agents
* create invalid dependency graphs
* use unauthorized artifacts
* bypass review gates

Run the same validation pipeline as initial plans.

---
