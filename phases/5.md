# MOST IMPORTANT RULE

## DO NOT START BY WRITING NEW FEATURES.

The first goal of this phase is:

> **Run the actual FlashTerminal application and show me what the product looks like today.**

Until you have inspected the real desktop application, do not start implementing a large UI redesign.

The source code is not sufficient.

Architecture diagrams are not sufficient.

Models are not sufficient.

The actual running product is the source of truth.

# FINAL PRINCIPLE

FlashTerminal has already proven that it can be:

* fast
* memory efficient
* multi-pane
* multi-agent
* orchestrated
* adaptive
* safe

Now prove that it can also be:

> **simple enough to understand, beautiful enough to want, and reliable enough to use every day.**

The goal of Phase 5 is not to make FlashTerminal capable of more things.

The goal is to make the capabilities that already exist **feel effortless.**
