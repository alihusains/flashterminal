# FlashTerminal Phase 3D

## Multi-Agent Collaboration + Artifact Handoffs + Result Synthesis

FlashTerminal Phase 3C is complete.

Current validated architecture:

```text id="q2z6ir"
User Intent
   ↓
Planner
   ↓
TaskGraph
   ↓
TaskScheduler
   ↓
ExecutionEnvironment
   ↓
WorktreeManager
   ↓
AgentRuntime
   ↓
Agent
   ↓
TaskResult / Artifact
   ↓
Human Review
   ↓
Merge
```

Phase 3C has established:

* Git worktree isolation
* deterministic branch naming
* base revision tracking
* execution environments
* dirty-workspace policies
* retry isolation
* artifact collection
* deterministic diff generation
* review gates
* approval
* rejection
* merge
* merge conflict detection
* cancellation preservation
* orphan detection
* persistence and recovery
* path traversal protection
* secret safety
* isolated 5-task parallel execution

Current gates:

```text id="j8jwxk"
workspace tests: PASS
Phase 3C tests: 11/11 PASS
clippy: 0 warnings
fmt: clean
release build: clean
```

Phase 3D introduces controlled multi-agent collaboration.

The fundamental principle is:

> **Agents collaborate through tasks, artifacts, and structured results, not through unrestricted direct process-to-process communication.**

---

# 1. Objective

Allow a workflow such as:

```text
Research
   ↓
Architecture
   ↓
Implementation
   ↓
Testing
   ↓
Security Review
   ↓
Final Review
```

to be executed by different agents where each agent receives the relevant outputs of previous tasks.

Example:

```text id="36k0k6"
Claude
  → Architecture report

Codex
  → Implementation

Pi
  → Tests

OpenCode
  → Security review
```

Each agent remains isolated in its own execution environment when appropriate.

---

# 2. Do NOT Implement Direct Agent Messaging

Do NOT build:

```text id="y6a1yq"
Agent A
   ↕
Agent B
```

direct sockets.

Do not let agents directly control each other.

Do not create:

```text id="h7bsv5"
send_message_to_agent()
```

yet.

Agents collaborate through:

```text id="3i4p2j"
Task
Artifact
TaskResult
Context
```

This keeps the system deterministic and auditable.

---

# 3. Introduce Artifact Handoff

A completed task should be able to expose artifacts to dependent tasks.

Conceptually:

```text id="2c5qyt"
Task A
  ↓
Artifact A
  ↓
Task B
```

Artifacts may include:

```text id="a4lc36"
source files
diffs
commits
test reports
research documents
architecture documents
logs
screenshots
structured data
URLs
```

Use the existing Artifact model.

Do not duplicate artifact systems.

---

# 4. Artifact Metadata

Ensure every artifact can identify:

```text id="2j4m8r"
artifact_id
type
created_by_task
created_by_agent
workspace
worktree
revision
path
description
created_at
```

Do not store credentials.

# 6. Artifact Selector

Create:

```text id="9m9h6y"
ArtifactSelector
```

Responsibilities:

```text id="4c1xyp"

```

Do not automatically dump every previous artifact into the next agent's context.

---

# 7. Context Builder

Extend the existing PlannerContextBuilder / TaskContext architecture.

Create:

```text id="f3s8t0"
TaskContextBuilder
```

For a dependent task, context may include:

```text id="d3qk8w"
task description
dependency results
relevant artifacts
repository state
relevant files
test results
review feedback
```

Context must be bounded.

Do not include unlimited previous output.

---

# 8. Explicit Artifact Dependencies

Tasks should be able to declare:

```text id="k2f04x"
input_artifacts
```

Example:

```json id="mx50li"
{
  "task": "security-review",
  "input_artifacts": [
    "implementation-diff",
    "test-report"
  ]
}
```

The scheduler must validate that those artifacts exist before execution.

---

# 9. Artifact Readiness

A dependent task should not start if a required artifact is unavailable.

Example:

```text id="5zghf3"
Implementation
   ↓
creates auth.diff
   ↓
SecurityReview
```

If `auth.diff` is missing:

```text id="8tv1jf"
SecurityReview = Blocked
```

Do not silently continue.

---

# 10. Artifact References vs File Paths

Prefer structured artifact references over arbitrary filesystem paths.

Example:

```text id="s7u8ge"
artifact://task-123/diff
```

rather than:

```text id="7fpgzr"
/tmp/foo/bar.diff
```

The Artifact layer resolves the physical location.

This will make future remote execution possible.

---

# 11. Cross-Worktree Artifact Consumption

Task B may run in a different worktree from Task A.

Therefore:

```text id="t3a6y2"
Task A worktree
       ↓
Artifact
       ↓
Task B worktree
```

must work.

Do not assume shared filesystem state.

---

# 12. Repository Artifact vs Knowledge Artifact

Distinguish:

### Repository artifacts

```text id="g6r4h0"
diff
commit
file
test output
```

### Knowledge artifacts

```text id="ab6sgp"
research
architecture
decision
review
summary
```

Knowledge artifacts may not need to exist in Git.

Do not force every artifact into a repository commit.

---

# 13. Structured Agent Results

Extend `TaskResult` to support structured results.

Conceptually:

```text id="drwhh7"
TaskResult {
    status
    summary
    artifacts
    metrics
    warnings
    errors
    recommendations
}
```

Do not require an LLM to generate summary fields.

Use deterministic fields where possible.

---

# 14. Result Synthesis

Create:

```text id="vyx8c6"
ResultSynthesizer
```

Its purpose is to combine outputs from multiple tasks.

Example:

```text id="kyi1km"
Architecture
+
Implementation
+
Tests
+
Security Review
        ↓
Final Result
```

Phase 3D may use an LLM for synthesis.

However:

> The synthesizer must only receive explicitly selected TaskResults and Artifacts.

Never send the entire project history by default.



# 21. Severity Model

Use:

```text id="2a1zv7"
Info
Low
Medium
High
Critical
```

Aggregate according to policy.

Example:

```text id="zs8c3a"

```

Make rules configurable.

# 38. Security

Do not allow artifacts to become a secret-leak path.

Test:

```text id="7o9t2u"
API key in agent output
private environment variable
credential-like content
```

Ensure redaction occurs before artifact persistence.

---

# 39. Cross-Agent Security

Agents should only receive artifacts explicitly granted to their task.

Test:

```text id="gmbf67"
Task A artifact
Task B has no dependency on A
```

Task B must not automatically receive A's artifact.

---

---

# 41. Agent Memory Boundary

This prevents uncontrolled context growth.
