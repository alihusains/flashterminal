# 1. Primary Objective

Phase 3B introduces intelligence into the orchestration layer.

The user should eventually be able to express:

```text id="tlq8d4"
Build authentication with Google and GitHub.
```

and FlashTerminal should be able to:

1. understand the intent
2. inspect the workspace
3. propose a task plan
4. select appropriate agents
5. validate the plan
6. ask for approval where necessary
7. execute the deterministic TaskGraph
8. monitor progress
9. review results
10. propose follow-up work

The deterministic task engine remains the execution authority.

---

# 2. Fundamental Rule

The LLM is a:

> **Planner**

It is NOT:

> **Orchestrator**

The architecture must remain:

```text id="87v1y9"
LLM Planner
     ↓
ProposedPlan
     ↓
PlanValidator
     ↓
Validated TaskGraph
     ↓
TaskScheduler
     ↓
AgentRuntime
```

Never:

```text id="riib3b"
LLM
 ↓
raw shell command
 ↓
spawn process
```

The Planner must never bypass:

* AgentRuntime
* PermissionPolicy
* TaskScheduler
* concurrency limits
* budgets
* persistence
* auditability

---

# 3. Introduce Planning Domain

Create a separate planning domain.

Conceptually:

```text id="k31wqa"

PlannerResponse

```

Keep these separate from:

```text id="g2xjrv"

```

A proposed plan becomes an executable TaskGraph only after validation.

# 9. Structured Planner Output

The planner must return structured output.

Do NOT parse arbitrary prose to construct the task graph.

Use a schema such as:

```json id="qbl6ag"
{
  "goal": "Implement authentication",
  "tasks": [
    {
      "id": "research",
      "title": "Inspect authentication architecture",
      "description": "...",
      "agent": "claude-code",
      "depends_on": []
    },
    {
      "id": "implement",
      "title": "Implement Google/GitHub auth",
      "description": "...",
      "agent": "codex",
      "depends_on": ["research"]
    }
  ]
}
```

Validate the schema before constructing Task objects.

# 20. Planning Failure

```text id="p9xn4l"

cycle
```

Do not attempt uncontrolled string parsing as a fallback.

Provide a retry mechanism with a corrected schema request.
